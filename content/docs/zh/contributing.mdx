### 2. 拉取复刻项目到本地

Fork 项目后，复制项目的 git 链接，例如 `https://github.com/你的用户名/hello-adp.git`

![image.png](https://s2.loli.net/2025/05/18/PvtSY6hZ4xsO8FN.png)

进入终端，在需要的位置克隆项目，使用以下命令：

```shell
git clone https://github.com/你的用户名/hello-adp.git
```

### 3. 编辑 mdx 文档

我们非常推荐你使用 AI 辅助的 IDE 完成文档撰写（例如 Cursor、Windsurf、Cline等）。

新建窗口，选择目录进入项目。

本项目的目录结构如下：

```
content/                   # 文档内容主目录
├── docs/
│   ├── en/                # 英文文档
│   │   ├── meta.json      # 顶层导航配置
│   │   ├── index.mdx      # 首页文档
│   │   ├── quickstart.mdx
│   │   ├── contributing.mdx
│   │   ├── workflow/
│   │   │   ├── meta.json
│   │   │   └── node/
│   │   │       ├── meta.json
│   │   │       └── parameter-extraction.mdx
│   │   └── ...            # 其他板块（playground/、plugin/ 等）
│   └── zh/                # 中文文档（结构与 en 相同）
│       ├── meta.json
│       ├── index.mdx
│       ├── quickstart.mdx
│       └── ...
```

其中，每个文档目录下的结构基本遵循以下原则：

1. `meta.json` 文件：控制该目录下的文档在导航菜单中的显示顺序和结构，例如：
   ```json
   {
       "title": "文档标题",
       "icon": "图标名称",
       "defaultOpen": true,
       "pages": [
           "文档名1",
           "文档名2",
           "子目录名"
       ]
   }
   ```
   本项目使用的图标包是 [RemixIcon](https://remixicon.com/)

2. 文档文件（`*.mdx`）：实际内容，必须包含frontmatter（文件头部的YAML信息块），例如：
   ```yaml
   ---
   title: 文档标题
   description: 文档描述
   enableComments: true
   author: "作者名"
   github_username: "GitHub用户名"
   x_username: "X用户名"
   ---
   ```

3. 子目录：用于进一步组织内容。每个子目录在不同语言目录下都需要有各自的 `meta.json`。

文档在不同语言中的文件名保持一致，只是存放在对应的语言目录中，例如：

- 中文：`content/docs/zh/getting-started.mdx`
- 英文：`content/docs/en/getting-started.mdx`
- 日文：`content/docs/ja/getting-started.mdx`

#### 多语言化（i18n）

你只需要写一个语言的内容，剩下的可以交给 Cursor 来完成。

本项目内置了 Cursor rule： `.cursor/rules/i18n.mdc`

你需要通过 `@` 添加 `i8n.mdc` ，以下的 prompt 可以作为参考：

```
帮我把 content/docs/en/xxx.mdx 翻译到 content/docs/<locale>/xxx.mdx
```

![image.png](https://s2.loli.net/2025/05/18/PwH4iSQTJGpLtkv.png)

Cursor rule 中内置了如何在 `content/docs/<locale>/` 下放置文件以及更新各语言目录的 `meta.json`。

#### 图片

本项目通过 `next.config.mjs` 控制域名白名单，目前放行的图床是 [sm.ms](https://sm.ms)，方便集中管理图片。

如果你使用了其他图片托管方案，请修改 `next.config.mjs`，但依然要遵循统一存放的原则。

我们强烈建议你在在截图之前将语言设置为英文，方便不同语言的读者阅读。

### 4. 测试

在提交之前，请先完成本地测试确保能够正确编译。下面是测试步骤：

#### 安装依赖

首先，确保已安装所有依赖：

```bash
# 使用 npm
npm install

# 或使用 yarn
yarn
```

#### 本地运行

启动开发服务器查看效果：

```bash
# 使用 npm
npm run dev

# 或使用 yarn
yarn dev
```

访问 `http://localhost:3000` 检查你的文档是否正确显示。

#### i18n 完整性检查

**重要提示**：确保完成所有语言版本的文档。默认情况下，如果没有创建英语（`.mdx`）文件，其他语言的文档都无法通过编译。

必须完成的文件：

1. 英文版本（基础版本）：`content/docs/en/document.mdx`
2. 中文版本：`content/docs/zh/document.mdx`
3. 日文版本：`content/docs/ja/document.mdx`
4. 各语言的元数据文件：`content/docs/en/meta.json`、`content/docs/zh/meta.json`、`content/docs/ja/meta.json`

检查方法：

- 运行 `yarn build` 或 `npm run build` 进行构建测试
- 观察控制台是否有编译错误
- 常见的错误包括：
  - 缺失某语言版本的文档
  - frontmatter格式错误
  - meta.json中引用了不存在的文档
  - 图片链接失效

如果发现编译错误，请根据错误信息修复问题后再提交。

#### 测试所有语言版本

切换不同语言查看文档：
- 英文版：`http://localhost:3000/docs/en/...`
- 中文版：`http://localhost:3000/docs/zh/...`
- 日文版：`http://localhost:3000/docs/ja/...`

确保所有语言版本都能正确显示，并且内容一致。

## 提交用例或反馈

如果你希望提交用例，且希望我们来帮助你完成正文的话，可以向本仓库提交Issue。

<Cards>
  <Card 
    icon={<i className="ri-github-fill ri-lg" />}

    title="GitHub Issue"

    向本项目提交用例或反馈
  </Card>

Issue格式参考如下：

```markdown
## 标题
[这里填写用例标题]

## 描述
[简单描述这个用例的功能和目的]

## 项目链接
[列出项目的链接，比如 Workflow 的 DSL 文件]

## 原文链接
[提供与用例相关的原文、链接或文档，比如项目 README]

## 其他信息
[任何其他需要说明的内容]
```

我们的会评审您提交的Issue，并在接受后为您创建相应的文档。如有问题或需要进一步讨论，请在Issue中留言。
