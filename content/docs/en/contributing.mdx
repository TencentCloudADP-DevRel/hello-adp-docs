## Submit a Use Case

Follow these steps if you would like to add a new example to the project.

### 2. Clone your fork

After forking, copy the git URL for your repository—for example `https://github.com/<your-username>/hello-adp.git`.

![image.png](https://s2.loli.net/2025/05/18/PvtSY6hZ4xsO8FN.png)

Run the following command in the directory where you want to work:

```shell
git clone https://github.com/<your-username>/hello-adp.git
```

### 3. Edit the MDX content

We highly recommend an AI-assisted IDE such as Cursor, Windsurf, or Cline to speed up authoring.

Open the project in a new window and review the structure:

```
content/                   # Docs root
├── docs/
│   ├── en/                # English sources
│   │   ├── meta.json      # Top-level navigation config
│   │   ├── index.mdx      # Landing page
│   │   ├── quickstart.mdx # Quickstart guide
│   │   ├── contributing.mdx
│   │   ├── workflow/
│   │   │   ├── meta.json
│   │   │   └── node/
│   │   │       ├── meta.json
│   │   │       └── parameter-extraction.mdx
│   │   └── ...            # Additional sections (playground/, plugin/, etc.)
│   └── zh/                # Chinese sources (mirrors en/)
│       ├── meta.json
│       ├── index.mdx
│       ├── quickstart.mdx
│       └── ...
```

Each locale lives under its own folder inside `content/docs`. Keep the directory tree identical across languages so navigation metadata stays in sync.

Each folder follows the same principles:

1. `meta.json`: controls ordering and structure in the navigation drawer. Example:
   ```json
   {
       "title": "Section title",
       "icon": "remix-icon-name",
       "defaultOpen": true,
       "pages": [
           "doc-slug-1",
           "doc-slug-2",
           "sub-folder"
       ]
   }
   ```
   We use the [Remix Icon](https://remixicon.com/) set throughout the project.

2. `*.mdx`: the actual document. Always include a frontmatter block at the top:
   ```yaml
   ---
   title: Document title
   description: Short description
   enableComments: true
   author: "Your name"
   github_username: "your-github"
   x_username: "your-x-account"
   ---
   ```

3. Subfolders: further organize content. Each subfolder also needs its own `meta.json` file per locale directory.

Document filenames are shared across locales. Use the same slug inside every language folder, for example:

- English: `content/docs/en/getting-started.mdx`
- Chinese: `content/docs/zh/getting-started.mdx`
- Japanese: `content/docs/ja/getting-started.mdx`

#### Localization workflow (i18n)

Write one language first and let Cursor handle the rest.

The repo ships with an i18n rule at `.cursor/rules/i18n.mdc`.

Summon it with `@i18n.mdc` inside Cursor. A sample prompt:

```
Translate content/docs/en/xxx.mdx into the remaining locales under content/docs/<locale>/xxx.mdx.
```

![image.png](https://s2.loli.net/2025/05/18/PwH4iSQTJGpLtkv.png)

The rule documents how to place files under `content/docs/<locale>/`, update each locale's `meta.json`, and keep variants in sync.

#### Images

Image hosting is limited through `next.config.mjs`. We currently allow [sm.ms](https://sm.ms) so assets stay centralized.

If you prefer a different CDN, update `next.config.mjs` accordingly while keeping assets well organized.

We strongly recommend capturing screenshots in English to make cross-language review easier.

### 4. Test locally

Run the project before opening a PR to make sure everything builds correctly.

#### Install dependencies

```bash
# npm
npm install

# or yarn
yarn
```

#### Start the dev server

```bash
# npm
npm run dev

# or yarn
yarn dev
```

Visit `http://localhost:3000` and confirm your docs look good.

#### Verify i18n completeness

**Important:** every language variant must exist. Without an English (`.mdx`) file, other locales will fail to compile.

Make sure you have:

1. English base file: `content/docs/en/document.mdx`
2. Chinese variant: `content/docs/zh/document.mdx`
3. Japanese variant: `content/docs/ja/document.mdx`
4. Navigation metadata for each locale: `content/docs/en/meta.json`, `content/docs/zh/meta.json`, `content/docs/ja/meta.json`

Check with:

- `yarn build` or `npm run build`
- Watch for errors such as missing locale files, malformed frontmatter, mismatched entries in `meta.json`, or broken image URLs.

Inspect every locale in the browser:
- English: `http://localhost:3000/docs/en/...`
- Chinese: `http://localhost:3000/docs/zh/...`
- Japanese: `http://localhost:3000/docs/ja/...`

All variants should render correctly and convey the same message.

## Submit a use case or feedback

If you have an idea but would like us to draft the final copy, open an Issue in this repository.

<Cards>
  <Card 
    icon={<i className="ri-github-fill ri-lg" />} 
    href="https://github.com/stvlynn/hello-adp/issues/new" 
    title="GitHub Issue"
  >
    Share a use case or request support.
  </Card>
</Cards>

Use the following template:

```markdown
## Title
[Provide a short title for the use case]

## Description
[Describe what the workflow or demo accomplishes]

## Project links
[List any relevant repos, workflow DSL files, or demos]

## Source material
[Attach references such as READMEs or articles]

## Additional notes
[Any other context reviewers should know]
```

We will review the Issue, follow up with any questions, and publish the documentation after acceptance.
